# Панель управления AmneziaWG

Самостоятельная русскоязычная Flask-панель для одного существующего интерфейса `awg0`. Она импортирует уже созданные пиры, показывает runtime-статистику и состояние VPS, отображает во всплывающем окне QR и текст обычных `.conf` и зашифрованных `.vpnuri`, поддерживает поиск, фильтры, заметки, метки, скачивание, переименование, временное отключение, включение и удаление клиентов.

## Требования

- Ubuntu/Debian с Python 3.11 или новее;
- установленный и работающий AmneziaWG, команда `awg` и интерфейс `awg0`;
- конфигурация `/etc/amnezia/amneziawg/awg0.conf`;
- существующие клиентские файлы в `/root/awg`;
- UFW уже разрешает TCP 8080 только с доверенных IP.

## Установка на VPS

Скопируйте проект на сервер и выполните:

```bash
sudo bash deploy/install.sh
```

Установщик попросит пароль администратора и публичный Endpoint вида `203.0.113.10:51820`, создаст отдельного пользователя `amnezia-panel`, виртуальное окружение и systemd-сервис. Панель будет доступна по адресу `http://IP_СЕРВЕРА:8080`.

При неинтерактивном запуске задайте `AMNEZIA_INSTALL_ENDPOINT`. Установщик сгенерирует сильный пароль и сохранит URL, логин и пароль в `/root/amnezia-panel-credentials.txt` с правами `0600`.

HTTP допустим только внутри заявленного UFW-периметра. Если доступ выходит за доверенную сеть, включите TLS через отдельный reverse proxy или VPN-доступ к панели.

## Проверка и обслуживание

```bash
sudo systemctl status amnezia-panel
sudo journalctl -u amnezia-panel -f
sudo systemctl restart amnezia-panel
```

Параметры находятся в `/etc/amnezia-panel.env`, база — в `/var/lib/amnezia-panel/panel.db`, журнал — в `/var/log/amnezia-panel/panel.log`. После правки окружения перезапустите сервис.

Чтобы изменить пароль, выполните `cd /opt/amnezia-panel && sudo -u amnezia-panel .venv/bin/python -m tools.hash_password`, перенесите полученный хеш в `AMNEZIA_PANEL_PASSWORD_HASH` и перезапустите сервис. Не помещайте хеш в кавычки командной оболочки с интерполяцией `$`.

## Совместимость и безопасность

Панель сохраняет неизвестные поля `[Interface]` и `[Peer]`. Новые клиенты создаются штатным `/root/awg/manage_amneziawg.sh` через root-owned helper `/usr/local/sbin/amnezia-panel-add`, поэтому получают совместимый маркер `#_Name`, `.conf`, `.png`, `.vpnuri` и `.vpnuri.png`. Для локальной разработки без helper остаётся изолированный fallback, который не используется стандартной VPS-установкой.

Все команды запускаются без shell и имеют allowlist. Helper принимает ровно одно имя по `^[A-Za-z0-9_-]{1,63}$`, очищает окружение и фиксирует путь/аргументы управляющего скрипта. Пароль хранится как Argon2id-хеш, сессия — на сервере по SHA-256 от непрозрачного cookie, формы защищены CSRF, после пяти ошибок вход блокируется на 15 минут. Системный пользователь имеет `CAP_NET_ADMIN`, traversal-доступ к закрытым родителям `/root` и `/etc/amnezia`, нерекурсивный ACL на клиентские файлы и две sudo-команды: фиксированный рестарт `awg0` и вызов add-helper. Компрометация панели в таком режиме позволяет создать VPN-клиента, но не предоставляет произвольную root-оболочку.

## Резервная копия и восстановление

Кнопка «Резервная копия» скачивает ZIP с консистентным SQL-дампом SQLite, `awg0.conf` и безопасным снимком списка клиентов. Архив содержит конфигурацию сервера и должен храниться как секрет. Для восстановления остановите сервис, сохраните текущие файлы, создайте чистую базу командой `sqlite3 panel.db < panel.sql`, замените `awg0.conf`, выставьте прежние владельца/права и запустите сервис. Клиентские `.conf` содержат private keys и копируются отдельно из `/root/awg` защищённым каналом.

## Локальные тесты

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m pytest tests -s -v
```

Тесты работают с временными файлами и внедрённым runner, поэтому не вызывают `awg` и не меняют VPN текущей машины.

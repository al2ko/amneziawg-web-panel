# Панель управления AmneziaWG

Русскоязычная веб-панель для управления **уже установленным** AmneziaWG на одном VPS с интерфейсом `awg0`. Панель не устанавливает VPN-сервер: она подключается к существующей конфигурации и импортирует имеющихся клиентов.

## Возможности

- Список клиентов с поиском, фильтрами, сортировкой, заметками и метками; состояние подключения, последний handshake, трафик и показатели VPS.
- Создание клиентов штатным скриптом AmneziaWG, просмотр и скачивание `.conf`, `.vpnuri` и QR-кодов.
- Переименование, отключение, включение, удаление и перегенерация конфигурации клиента с сохранением ключей и IP.
- Временные клиенты на 1 час, 12 часов, 1 день, 7 дней, 30 дней или 4 недели: срок виден в таблице по московскому времени, есть фильтры «Временные» и «Истекли».
- Авторизация администратора, журнал действий и скачивание резервной копии панели.

Срок действия обеспечивается штатным механизмом AmneziaWG: cron удаляет истёкшего клиента из VPN и его файлы при очередной проверке (обычно в течение 5 минут). В панели остаётся строка «Срок истёк», которую можно удалить вручную. Временного клиента нельзя переименовать, чтобы не нарушить автоматическое удаление.

## Требования к серверу

- VPS с Ubuntu/Debian, `systemd`, Python 3.11 или новее и доступом к пакетам `apt`/`pip` при обычной установке.
- Работающий AmneziaWG: команда `awg`, интерфейс `awg0`, файл `/etc/amnezia/amneziawg/awg0.conf`.
- Каталог `/root/awg` и штатный `/root/awg/manage_amneziawg.sh` для создания и перегенерации клиентов. На сервере с существующими клиентами их файлы также находятся в `/root/awg`.
- Доступ к TCP 8080 только с доверенных IP (например, через UFW). Если панель будет доступна за пределами доверенной сети, настройте TLS через reverse proxy или открывайте её через VPN.

Установщик сам устанавливает `python3`, `python3-venv`, `acl` и `cron`, создаёт пользователя и сервис панели. Перед запуском убедитесь, что установленная версия `python3` соответствует требованию 3.11+.

Если используете UFW, разрешите доступ к панели только со своего публичного IP (замените адрес в примере):

```bash
sudo ufw allow from 198.51.100.42 to any port 8080 proto tcp
```

## Установка на новом VPS

Устанавливать нужно **весь проект**, а не только `deploy/install.sh`: скрипт копирует исходники приложения, зависимости и служебные файлы из каталога проекта. Выполняйте следующие команды после установки AmneziaWG.

### Вариант 1 — из GitHub

На VPS клонируйте репозиторий и запустите установщик:

```bash
git clone https://github.com/al2ko/amneziawg-web-panel.git amnezia-panel-src
cd amnezia-panel-src
sudo bash deploy/install.sh
```

Скачивание **одного** установочного скрипта через `curl` не заменяет клонирование проекта.

### Вариант 2 — передать проект с компьютера без GitHub

На компьютере с локальным Git-репозиторием:

```bash
git archive --format=tar -o amnezia-panel.tar HEAD
scp amnezia-panel.tar USER@HOST:~/
```

На VPS (замените `USER` и `HOST` своими данными в команде `scp`):

```bash
mkdir -p ~/amnezia-panel-src
tar -xf ~/amnezia-panel.tar -C ~/amnezia-panel-src
cd ~/amnezia-panel-src
sudo bash deploy/install.sh
```

Архив из `git archive` содержит файлы текущего коммита; локальные незакоммиченные изменения в него не попадают.

### Что делает установщик

При интерактивном запуске он запросит пароль администратора панели и публичный VPN endpoint в формате `IP:порт` (например, `203.0.113.10:51820`). Затем установит приложение в `/opt/amnezia-panel`, создаст виртуальное окружение и запустит `amnezia-panel.service`. Вход в панель: `http://IP_СЕРВЕРА:8080`.

Для неинтерактивного запуска задайте endpoint перед командой:

```bash
sudo AMNEZIA_INSTALL_ENDPOINT=203.0.113.10:51820 bash deploy/install.sh
```

В этом режиме генерируется пароль администратора; URL, логин и пароль записываются в `/root/amnezia-panel-credentials.txt` с правами `0600`. При повторном запуске, если `/etc/amnezia-panel.env` уже существует, установщик сохраняет существующие учётные данные — новый пароль не выдаётся.

На VPS без исходящего интернета обычный установщик не сможет получить пакеты через `apt` и `pip`: подготовьте и передайте системные пакеты и Python-зависимости отдельно либо обеспечьте доступ к локальному зеркалу.

## Проверка и обслуживание

```bash
sudo systemctl status amnezia-panel
sudo systemctl status awg-quick@awg0
sudo systemctl status cron
sudo journalctl -u amnezia-panel -n 100 --no-pager
```

Настройки: `/etc/amnezia-panel.env`; база: `/var/lib/amnezia-panel/panel.db`; журнал: `/var/log/amnezia-panel/panel.log`. После изменения настроек перезапустите панель командой `sudo systemctl restart amnezia-panel`.

Для смены пароля создайте Argon2id-хеш командой `cd /opt/amnezia-panel && sudo -u amnezia-panel .venv/bin/python -m tools.hash_password`, перенесите его в `AMNEZIA_PANEL_PASSWORD_HASH` в `/etc/amnezia-panel.env` и перезапустите сервис. При ручной записи хеша не допускайте интерполяции символов `$` командной оболочкой.

## Перенос на другой сервер и резервные копии

Свежая установка панели на другом VPS **не переносит** пользователей VPN и их ключи. Для переноса существующего сервера сохраните данные AmneziaWG, включая `/etc/amnezia/amneziawg/awg0.conf`, клиентские файлы и ключи в `/root/awg`, а также базу панели `/var/lib/amnezia-panel/panel.db`. Для временных клиентов нужны `/root/awg/expiry` и `/etc/cron.d/awg-expiry`. Перенос выполняйте защищённым каналом и учитывайте новый публичный endpoint.

Кнопка «Резервная копия» скачивает ZIP с SQL-дампом SQLite, `awg0.conf` и списком клиентов без их приватных ключей. Этот архив сам по себе **не** является полной резервной копией AmneziaWG: приватные клиентские конфигурации и expiry-метки сохраняйте отдельно. Архив с конфигурацией сервера храните как секрет.

## Совместимость и доступ

Панель сохраняет неизвестные поля `[Interface]` и `[Peer]`. Создание и перегенерация клиентов выполняются через ограниченные root-helper'ы и штатный `/root/awg/manage_amneziawg.sh`; чтение expiry-меток использует отдельный helper. Панель работает от пользователя `amnezia-panel`, пароль администратора хранится как Argon2id-хеш, формы защищены CSRF, сессии хранятся на сервере.

## Локальные тесты

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m pytest tests -q
```

Тесты используют временные файлы и не изменяют VPN на машине разработчика.
